# 2026-09-24 主程序流程修复审查说明

## 问题与改动

此前文字与语音共用执行入口，但接入层、任务队列、执行流程和任务记录仍会重新判断同一句话，完成检查也会混入供模型参考的历史提示。本轮修复这些判断分歧及已复现的延迟问题，不能据此认定全部架构和所有入口都已统一验收。

建议按以下顺序审查：

1. `server/cognition/task_concurrency.ts`、`execution_pipeline.ts`、`turn_flow.ts`：服务端接受的任务关系向后传递；过期编号或版本不能获得执行权；历史提示不能独立授权工具操作。
2. `server/cognition/action_continuation.ts`、`server/conversation/manager.ts`、`server/socket/chat.ts`、`voice.ts`：查询进度不重新获取执行权；补齐材料后沿用原任务；文字与语音消费相同的接续判断。
3. `server/cognition/missing_task_input.ts`、`execution_guard_recovery.ts`、`result_finalizer.ts`、`server/llm/adapter.ts`：明确源文件缺失时，从真实读取回执终止本轮工具队列及外层恢复；下一轮可以重试。新输出不存在、权限错误、其他文件的错误不适用此停止条件。
4. `execution_pipeline.ts` 与 `result_finalizer.ts`：执行和验收使用用户目标及本轮要求，历史提示仍供模型参考；路径中的 run、copy、发送、分析等字样不算额外动作。
5. `server/llm/model_turn_state.ts`、`providers.ts`、`adapter.ts`：一次用户请求的模型等待预算和不可用候选共享，内部恢复不能重新获得整份预算；新请求重新开始。`conversation_profile.ts` 等仅对明确闲聊降低可选推理开销，不授予工具权限。
6. `db_layer.ts`：交互、记忆、用量等集合的增量持久化和原子回滚，降低完整快照重复写入开销。

## 尚未覆盖

这轮是实际聊天接口及文件工具验收，没有重新做原生窗口、语音实机、全部网站或全部产品入口验收。多步任务仍有模型和持久化等待，不能称为即时响应。原有 `memory_auto_organize` 未知结果隔离仍在，整机健康检查并非全部通过。

Laya 离线接续试验与生产修复分开提交，详情见 `scripts/laya/README.md`。实验未达到启用标准，没有赋予执行权限，不能将这些脚本的提交理解为模型已接管主程序决策。
