# LumiCore 第五批：REST 与自主执行链路精简

日期：2026-09-25。基线 `35760c3`，工作区延续前四批未提交的修改。原始审计报告保留。

## 执行判断与复用

1. REST 原先把全部历史（包含助手和外部提供的 system/tool 内容）拼成当前操作指令。已改为只以最新用户消息授权本轮动作，历史用户/助手消息继续提供给模型理解；显式绑定的经营任务仍使用服务器核对过摘要的原始业务输入。
2. 统一 REST 对话消息整理，修复空 `messages: []` 吞掉 `message/prompt` 的问题，移除供应商专属的重复 Anthropic 消息整理函数。
3. 合并普通 JSON 和 SSE 的模型调用、结果验收、用量记录和最终回复；两者均返回经营工作流状态。保留普通聊天流式显示，执行类内容仍先验收再发送。删除两个分支必定返回之后的不可达收尾代码。
4. 把规范工具回执的观察和等待保存提取到 `server/tools/receipt_observer.ts`。前台/消息渠道原有会话归档，以及 REST 经营流程，复用同一观察器；相同规范记录的被动观察与严格保存回调共用一次写入。数据库故障向等待方传播，允许随后重试保存，不重新执行工具。

## 稳定性修复

| 问题 | 修复与验证 |
|---|---|
| REST 经营任务取消、断线或模型循环退出后，工具稍后返回时没有进入业务台账 | 在工具引擎生成规范结果的入口观察，写入原经营工作流的既有记录；不重启任务、不把 cancelled/blocked 改为完成 |
| 经营状态只更新内存就返回终态回复 | 最终状态和中断状态写盘；JSON 与 SSE 均等待最终保存。保存失败返回错误，不发送正常终态回复 |
| 组织身份在等待中撤销或重新加入 | 绑定原成员身份并复用组织授权观察器；撤权中断模型/工具信号并关闭 HTTP 响应，迟到输出不写入组织台账；重新加入不会继承旧请求 |
| 自主任务取消信号没有传给等待桌面控制权的队列 | 转发器接入自主执行器既有取消信号。实际持有前台租约、让自主任务排队后取消，验证队列立即退出、没有连接桌面，任务以 cancelled 收尾 |

自主队列原有动作启动、落盘和终态租约机制保留，不新增另一套自主任务台账。

## 隔离验收

- 真实 HTTP 请求及 SSE 解析；模型回复由受控替身提供，工具走真实引擎、隔离文件读取与 SQLite。
- 已先复现 REST 历史被当成当前指令、空历史吞掉输入，以及自主取消后仍在桌面队列等待，再验证修复。
- 新增经营任务迟到/断线、账号撤权与重新加入、保存等待/保存失败、JSON/SSE 一致性，以及共享规范回执保存屏障测试。
- 旧测试中两条仅匹配源码语句的 SSE 检查改由真实 HTTP 行为测试覆盖：普通聊天可流式显示，未经核实的执行完成声明不会提前发出。

未调用正式模型 API、未向第三方账号发消息、未操作用户的桌面。前台控制队列测试使用隔离的控制租约和受控桌面连接目标。

## 尚未完成

- 普通无绑定任务的 REST 调用仍为无状态接口，本批未让它自动创建桌面对话或任务。
- 经营任务被多个客户端同时启动、服务进程在工具尚未返回时被强制终止等情况，还需专门验收。本批的迟到归档以进程和数据库仍可用为前提。
- 迟到结果保存失败有错误记录及后续保存重试能力，未新增自动、跨进程的持久化重试队列。
- 主程序大文件拆分、其余调度路径和完整客户端实机验收尚未完成，不能把本批通过视为整体优化结束。

本轮未提交、推送或重启客户端。最终清理清单、测试和规模数据见下方收尾记录。
