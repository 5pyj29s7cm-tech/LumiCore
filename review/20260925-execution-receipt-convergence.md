# LumiCore 第三批精简与执行结果归档

日期：2026-09-25。基于主工作区 `35760c3` 之后尚未提交的连续优化。前两批记录见 [第二批说明](20260925-code-simplification.md)。原始 Claude 审计报告保持原样。

## 修复范围

本批处理的是“任务已取消或超时，工具稍后才返回，程序却忘记做过什么”的问题。没有重做新的决策器，也没有自动恢复已结束任务。

| 问题 | 修改后的行为 | 代码 |
|---|---|---|
| 文字/任务的模型循环退出后，迟到结果只留在旧回调中 | 三个前台入口使用同一个原始执行结果观察器，在工具引擎产出正式结果时归档 | `server/conversation/execution_receipt_archive.ts`，`server/socket/{chat,task,voice}.ts` |
| 语音另有一套取消后归档逻辑 | 删除语音专属迟到处理，保留用于有限等待的语音收集器；归档交给共享模块 | `server/socket/voice_execution_receipts.ts` |
| 桌面超时宽限期结束，真实结果稍后回来被 `settled` 丢弃 | 单独归档迟到结果；保存成功才确认接收和解除原生执行占用；保存失败允许重传，不重复操作桌面 | `server/socket/desktop_relay.ts`、`server/runtime/socket.ts` |
| 任务台账已有迟到结果，聊天记录与追问仍读到旧的未知占位记录 | 两处共用历史结果投影，按用户、工作域、组织、对话、请求和任务绑定读取有效回执 | `server/conversation/receipt_history.ts`、`manager.ts`、`execution_facts.ts` |
| 本地工具明确报告 `outcome_unknown` 却被归成普通失败/超时 | 执行结果封装将明确的未知结果保留为 `unknown_outcome` | `server/tools/execution_envelope.ts` |
| 旧的失败状态占位记录遮住真正迟到的失败 | 新未知占位使用 `outcome_unknown`；仅对同一请求、仍未核实的旧失败占位槽补入真实失败，保留数据库唯一约束 | `server/conversation/action_ledger.ts` |

归档补充原任务证据，不改任务完成状态、活动请求指针、下一轮租约或已发布的回复正文。正常到达的单个工具结果同样不能自行把整个任务判为完成。

正常回执为追加式存档。兼容修复仅允许把同一请求的 `tool_settlement_unknown`、核实状态为 `unverified` 的旧失败占位，补齐为真实失败；不覆写已确定的终态回执。否则 SQLite 原有唯一键会让真正的失败原因被占位记录挡住。新增回归已先复现该缺陷，再验证修复。

桌面迟到结果是底层子步骤的证据，仍标记“需要核实”。例如复合工具中的一次打开窗口返回，并不等于整套填表、保存、发送流程完成；这里不会伪造完整工具成功，也不会自动重放操作。

## 归属、权限与持久化

- 接收工具引擎正式生成且未被修改的结果；拒收伪造记录和不同任务/请求的记录。
- 创建观察器时复制并固定原始身份；检查原对话、任务、请求台账及组织授权，取消和后续对话不改变结果归属。
- 桌面保留原有可信原生进程校验、两阶段发送、重新连接与撤权后的停止专用流程；撤权后不会把旧组织输出内容送入归档回调。
- 复用现有脱敏和长度限制，不把密钥、截图二进制或无限长返回值直接复制到聊天存储。
- 历史读取校验持久化回执与封装中的任务、请求和工具字段，拒绝不一致记录。采用批量索引，避免逐条回执扫描全部请求。
- 复用现有回执表，无新增数据库表、后台轮询器或第二个执行调度器。

## 验证与边界

新增隔离测试执行真实工具引擎、本地临时文件写入、任务 Socket 和 SQLite 持久化；模型与原生桌面由受控测试替身提供。覆盖：取消之后实际完成、原任务/后继任务隔离、重复回执、伪造/撤权拒收、保存失败重传、敏感字段脱敏、聊天历史/追问一致、数据库重启后结果保留。

原有任务 Socket 测试只模拟模型回调，本批新增真正进入工具引擎的延迟工具用例。为使它走真实权限路径，测试按正常启动流程注册工具清单，未放宽生产权限或绕过检查。

尚未覆盖或解决：

- REST、第三方消息渠道、自主/调度入口的迟到结果处理还需逐入口验证，不能把本批三个前台入口视为全部渠道。
- 底层原生子步骤与复合工具整体结果的进一步核实仍需原执行器；不会仅凭子步骤回传自动恢复任务。
- 工具归档观察器出现数据库故障时会记录错误；正常请求仍靠既有终态持久化屏障，迟到普通工具结果的独立持久化故障重试队列尚未新增。原生桌面回传已具备保存失败不确认、允许重传的保护。
- 已保存回执经数据库重启可恢复，不代表未返回的桌面执行能跨整个服务进程重启自动续跑。
- 没有调用正式模型 API，没有操控用户正在使用的桌面，没有重启客户端，也未提交、推送。
