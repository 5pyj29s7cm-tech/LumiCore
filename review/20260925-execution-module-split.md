## 拆分目的和边界

本批整理三个与执行判断、最终回复和后台调度直接相关的大文件。保持既有公开调用路径、模型参数、判断顺序、任务状态和数据格式；把不同职责分开，避免后续修一个领域时继续往同一文件增加分支。本批不是重新增加一套判断器或调度器，也不以删除有效功能降低代码行数。

## 动作约束与证据

原 `server/cognition/action_contract.ts` 有 3,810 行。现有对话、语音、任务和消息渠道继续使用此入口，约束构建仍由同一套函数负责，领域核验移动到 `server/cognition/action_contract/`：

| 模块 | 职责 |
|---|---|
| `types.ts` | 动作种类、约束与能力要求的共享类型 |
| `intent.ts` | 从本轮输入提取所需动作和目标，不执行任务 |
| `receipts.ts` | 解析实际工具返回、展开已核实子结果、识别失败回执 |
| `desktop_evidence.ts` | 核对打开的目标、应用内修改、保存与后续观察 |
| `playback_evidence.ts` | 核对播放器、内容、播放/暂停状态和本轮记录范围 |
| `document_evidence.ts` | 核对当前应用中的文档、准确路径、读取内容和用户要求 |
| `evidence.ts` | 汇总各领域核验，保留原经营、CAD、网页登录及文件交付判断 |

旧入口保留原有导出，调用方无需批量更名。子模块不反向导入入口；各领域之间按单向依赖复用，不复制核验函数。

## 调度与后台任务

原 `server/scheduler.ts` 有 3,574 行，现作为公开入口。实现拆入 `server/scheduler/`：

| 模块 | 职责 |
|---|---|
| `runtime.ts` | 唯一调度实例及计时器、执行队列、取消、未知结果隔离、持久化确认 |
| `policy.ts` | 时间表达式、时限、执行规则和稳定的执行/送达编号 |
| `delivery.ts` | 主动消息最终核验，按用户及工作域选择到期提醒 |
| `builtin_tasks.ts` | 原有 27 项内置任务的注册与处理逻辑 |
| `types.ts` | 任务、执行上下文和送达等共享类型 |

保留原有实例、注册顺序、任务名称、调度周期、后台模型调用和取消信号。提醒仍由同一个调度器提交送达结果；内置任务不拥有另一套队列或状态记录。

## 验证方法

- 拆分前后 AST 对照：调度器 33 个、动作约束 170 个、最终回复验收 91 个顶层声明全部保留，函数体结构一致。三个公开入口原有的 23、54、5 个导出完全保留。仅导入路径和跨模块导出发生调整；动态导入按照原目标重定位。
- 原国际化基线只迁移路径：调度器 51 项、动作约束 87 项、最终回复验收 67 项现有字面量指纹和出现次数保持一致，没有扩大允许范围。
- 新增依赖边界测试，防止子模块反向依赖公开入口或形成模块循环；新增内置任务注册测试，确认 27 项任务各注册一次且使用同一个运行实例和有效执行策略。
- 4 处原来读取大文件源码的检查改为读取对应职责模块，保留其验证的持久化顺序、输出核验、系统扫描隔离和技能生成规则；任务注册的文本计数改为实际注册验证。
- 相关定向回归已覆盖任务取消、超时、迟到结果、提醒原子送达、周期任务、应用操作、文档和播放核验。未调用正式模型或控制用户桌面。

## 最终回复验收

`server/cognition/result_finalizer.ts` 保留原来的最终验收顺序及快速返回入口，辅助逻辑拆入 `server/cognition/result_finalizer/`：

| 模块 | 职责 |
|---|---|
| `types.ts`、`context.ts` | 统一输入输出类型、本轮身份、动作约束和回执有效性 |
| `claims.ts` | 根据本轮证据核对“已执行”“正在执行”等声明 |
| `desktop_results.ts` | 根据已核实桌面动作、应用修改、播放结果组织回复 |
| `artifact_results.ts` | 文件、文档、CAD 与生成媒体的交付说明 |
| `task_results.ts` | 工作流、技能、运行任务与只读观察的结果说明 |
| `wording.ts` | 阻塞说明，以及模型措辞与已核实结果之间的一致性 |

这几个模块不执行新的任务，不各自重做路由；仍由主验收函数按原顺序调用。原 `formatGroundedArtifactResult` 等公开导出继续可用。
