# LumiCore 第四批：消息渠道执行记录与跨对话归属

日期：2026-09-25。源码基线仍为 `35760c3`，工作区包含前三批尚未提交的优化。本批继续处理执行链路复用，原始 Claude 审计报告不变。

## 已修复

| 缺口 | 最终处理 |
|---|---|
| 微信、飞书、企业微信的模型循环返回前抛错，已经完成的工具结果没有进入终态回复 | 逐步收集工具结果，异常回复携带已收集记录，并明确任务受阻；不再把单步读取成功当作整项任务完成 |
| 模型循环已经结束，工具随后返回，消息渠道没有归档观察器 | 复用前台文字、任务、语音的 `createConversationReceiptObserver`，保存原请求结果；不恢复已关闭的请求，不改变后续任务 |
| 同一执行结果从引擎观察器、模型回调、最终返回多次到达，会重复进入进度记录 | 从结果恢复模块提取 `mergeToolExecutionRecords`，消息渠道和恢复链路共用；按任务、请求、工具和调用标识去重，不合并不同调用的真实前后观察 |
| 消息渠道的桌面转发缺少原任务/请求绑定和迟到结果持久化入口，退出路径未统一释放控制权 | 两种桌面转发均传入原任务、请求、取消信号和共享归档回调；所有出口统一释放桌面租约，未结束的物理动作仍受原转发器的占用保护 |
| 任务执行过程中用户新开聊天，旧消息的回复写进新聊天 | 接收、执行、写回均通过已存用户消息定位原会话；保留用户、组织与工作域校验，不迁移到当前活动会话 |
| 停止消息接入被归档回调当作撤权，进程尚在收尾时仍丢弃迟到结果 | 执行准入与归档授权分开；停止接入仍禁止新工作，但已开始工作的结果只核对原账号/组织授权 |

未新增决策器、执行调度器、数据库表或自动重试任务。恢复模块原有的局部合并函数已经移除，替换为共用函数。普通终态结果保持不可变；桌面执行计划的汇总快照允许由同请求的新快照更新。

## 回归证据

新增 `test/messaging_execution_receipts.test.ts`：模型接口为测试替身，调用真实消息处理入口、工具引擎、本地隔离文件读取及 SQLite。覆盖三种渠道后续模型超时、工具迟到、撤销账号绑定、两种桌面转发的任务绑定及释放、未核实原生子步骤、换聊天后归属、只有读取任务也不能在回复失败后误报完成。

先复现了三渠道丢失已完成记录、迟到工具丢失、桌面转发缺少任务绑定、旧回复串入新会话，以及停止接入后丢弃已有工作的结果，再验证修复。新增共享合并函数回归检查同次调用去重、不同观察保留、不同请求隔离及汇总快照更新。

针对性回归：8 个测试文件、137 项通过；补充退出收尾修复后，消息专项 9 项通过。最终完整测试及统计见下文。

## 本轮检查但未改动的部分

- 自主执行器已有 `prepare/start/settleAutonomousTaskAction`、精确租约及启动前持久化屏障。相关持久化生命周期测试通过。本轮未把前台的请求台账生硬套进自主队列，也不据此宣布自主桌面迟到子步骤全部验收。
- REST 行业流程已有逐步观察 `observeIndustryWorkflowTool`，但异常退出后的迟到结果、无行业任务的普通 REST 请求仍需进一步专项验证。
- 普通迟到工具的归档写入失败，目前仍是记录错误；本批未增加持久化重试队列。原生桌面迟到结果沿用上一批“保存成功才确认接收，失败可重传”的机制。
- 停止接入后的归档测试以进程和数据库仍可写为前提，不代表服务进程已退出后还可接收结果或跨重启恢复未结束的工具。
- 尚未使用正式模型 API、真实飞书/微信账号发送消息或控制用户桌面；本轮是代码与隔离集成验收。

未提交、未推送、未重启客户端。
