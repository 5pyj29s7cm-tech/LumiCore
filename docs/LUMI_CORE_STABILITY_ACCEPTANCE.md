# Lumi 核心能力长期稳定化目标与验收基线

本文件是长期目标的仓库内事实源。聊天上下文压缩、重新启动开发会话或更换维护者时，都应从这里和自动化测试恢复目标，不能把“代码已写”当成“实际体验已验收”。

## 约束

- 在用户明确解除前，不提交、不推送、不创建远程 PR、不触发远程构建或发布。
- 外部发送、发布、提交等副作用必须确认；未知结果停止，不盲目重试。
- 本地操作也必须命中精确目标并有真实回执。
- 最终完成结论来自持久回执，模型叙述不能覆盖已验证事实。

## 稳定化范围

### P0-1 模型选择与路由

- 固定模型绝对固定，不允许通道层偷偷换模型。
- 有序回退只执行用户配置的顺序；自动模式的真实选择、失败原因和每次尝试写入路由回执。
- 聊天、语音、任务和内部智能体共享同一模型策略。
- 自定义 `ext_*` Provider 与内置 Provider 使用同一固定/回退管线；停用后保留用户原选择并明确失败，不静默改写。

### P0-2 本地模型运行时

- Ollama、LM Studio 使用真实 `/models` 和推理探测，不以进程存在代替可用。
- 具备队列、超时、预热、失败退避、断线重连和运行指标。

### P0-3 持久后台任务

- 后台委派和自治队列写入 SQLite，具有租约、检查点、重启恢复、取消和终态回执。
- 聊天可继续进行，后台任务状态不依赖单一内存指针。

### P1-4 桌面控制

- 全局桌面租约协调聊天、语音、任务和自治调用。
- 用户活动时暂停，执行前后绑定窗口身份；冲突不并发抢夺桌面。
- 完成必须有窗口、控件、视觉或应用回执，进程存在不等于完成。

### P1-5 外部 AI 协同

- 路由优先级固定为 API/MCP、健康 CLI、结构化浏览器、桌面视觉。
- 每个目标有持久会话、精确目标、幂等派发和独立回执。
- 结果未知时不切换路径重发；迟到答案归档到原会话。

### P1-6 外部 AI 历史

- 仅从已确认授权的 connector、JSON 导出、授权会话适配器或单个可见视口读取。
- 增量游标、稳定消息 ID、去重、附件、来源证据和重启检查点持久化。
- 历史读取不会提交新 prompt；可见桌面抽取不滚动、不发送，并标记为部分可见。

### P2-7 扩展与 Provider 注册表

- 只接受 Ed25519 签名的声明式 API v1 清单，不加载任意 JavaScript、Python、Shell 或安装代码。
- 支持 OpenAI-compatible Provider、沙箱 HTTP 工具或二者组合。
- 权限限定到精确 origin、凭据引用、本地网络、超时、请求/响应字节和并发预算。
- 具备 SSRF 防护、禁重定向、能力/副作用声明、外发确认、幂等与只读对账。
- 激活、升级、回滚、停用和重启恢复有持久修订与回执；失败恢复上一个活动版本。
- 设置页动态展示已激活 Provider；Lumi 自我模型明确其能力与边界。

## 发布门禁

完成状态必须同时满足：

1. 全量单测、TypeScript、i18n、React hooks 与安全审计通过。
2. 桌面 UI、服务端和桌面资源构建通过。
3. SQLite 完整性、打包首启冒烟、安装包冒烟通过。
4. 生命周期压力测试与运行时 soak 达到目标；两小时/至少 200 轮人工混合调用由用户做最终实际验收。
5. 无错误/重复外部副作用；路由和终态均有可追溯回执。
