# Lumi 历史稳定性验收说明（2026-08-07—08）

本文件只保留可公开的历史验收范围与方法，不引用真实用户会话、语音、任务、回执、数据库路径或设备标识。所有可公开回归均应使用隔离的临时数据根、合成夹具和去标识化结果；正式用户数据只能在本机、经用户授权后做原位完整性检查，不能进入源码仓库或 CI 产物。

## 历史验收范围

- 对话意图、工具路由与跨轮任务隔离。
- 工具、桌面控制、模型调用和语音链路的终态回执。
- 本地模型上下文预算、失败降级与恢复。
- 调度账本压缩、去重和重启恢复。
- SQLite 忙碌状态、完整性检查和安全关闭。
- 桌面构建、打包后端、Socket 握手与资源预算。

## 可公开的验证方法

| 门禁 | 公开证据要求 |
|---|---|
| 单元与集成测试 | 使用仓库测试夹具，报告测试文件数、测试项数与退出码 |
| TypeScript / Hooks / i18n | 运行 `npm run lint`，不得依赖正式用户数据 |
| SQLite | 在临时数据根创建合成数据库，执行完整性与外键检查 |
| 桌面构建 | 从当前提交重新生成前端、后端与桌面资源 |
| 打包冒烟 | 在隔离临时目录验证健康端点、Socket 与首启流程 |
| 资源预算 | 由当前构建产物计算，不复用历史 manifest |
| 差异检查 | `git diff --check` 无错误，并完成敏感信息扫描 |

## 不由自动化替代的事项

- 真实麦克风、扬声器、窗口缩放、系统权限和第三方客户端需要在目标设备上实测。
- Windows 与 macOS 安装包必须从同一已审查提交重新生成。
- 签名、notarization、更新通道和商业发布批准属于独立发布门禁。

这是一份历史方法说明，不是当前版本的通过证明。当前 LumiCore 版本只能以本轮重新生成的测试、构建、实机与 CI 回执作为交付证据。
